Python 虚拟机原理

Python虚拟机有个很明显的特点, 一切皆对象. (虽然代码是用c语言实现的)

第一次见C用面向对象的思想, CPython中主要是用宏来进行定义.

PyObject对象

这个是Python对对象的表示方式

总结一下Python Object的特点:

  • object有一个引用计数, 确保垃圾回收功能
  • Object的类型是PyObject *
  • Object 的内存和地址是保持不变的, 如果是变量的, 通过指向变量内存的指针实现

code对象

这个是Python对运行代码的表示, 比如说运行一个函数, 他会先用这个PyCodeObject生成一个对象, 然后运行的时候从中获取所需要的信息加以执行

从中我们可以大概知道:

  • 一个PyCode对象的类型是通过检查PyObject_HEAD中的ob_type来确定的
  • 一个PyCode对象包含了运行一段代码, python所需要的信息, 其中比较重要的是字节码

PyTypeObject

这个对象是一个很特殊的对象, 其他的对象都是在堆上静态分配的, 但是这个对象不是的, 它是静态分配的. 作为标识对象的类型的一个对象, 可以看到在PyObject_HEAD中定义了一个指向他的指针ob_type

运行原理

在其中的PyEval_EvalFrameEx函数是执行虚拟机指令的代码, 之后的获取虚拟机的opcode之类的操作全部都是由宏实现…

说一些题外话

从他的push和pop的宏可以看出, 他的sp指针一般指向栈顶的一个空闲位置, 而且他的栈中存储的是PyObject对象

劫持程序执行流

现在可以执行任意字节码了, 但是还是不够, 我们需要一个函数指针, 假如能改掉这个函数指针, 那么我们就可以控制程序执行流了

确实非常幸运, 恰巧有这么一个函数指针:

如何调用到这个函数指针:

Object/ceval.c 中字节码为CALL_FUNCTION时,
–> call_function()
–> do_call()
–> PyObject_Call()
–> 目标函数指针

总结一下, 如何调用到函数指针

i. 字节码类型为 CALL_FUNCTION, 进入call_function
ii. ob_type != PyCFunction_Type 或者 (oparg>>8) & 0xff < 0
(师傅说这个地方还不能是PyMethod_Type, 这个源码上看的不太懂, 感觉这个无所谓)
iii. ob_type != PyFunction_Type, 进入do_call
iv. ob_type != PyCFunction_Type 进入PyObject_Call
v. func->ob_type->tp_call 为我们调用的函数指针

最终思路:

  1. 用PyStringObject伪造PyTypeObject
  2. 伪造PyObject, 让他的type指向前面伪造的PyTypeObject
  3. 第三个Object存放指向fake_PyObject的指针
  4. 计算offset, 用EXTENDED_ARG拓展寄存器, LOAD_CONST将fake_PyObject压入数据栈, 调用CALL_FUNCTION劫持程序流

至此, 我们就成功控制了程序执行流. 接下来想要getshell我们还需要leak出一些信息

任意地址读

任意地址读选择的是PyByteArrayObject这个对象, 可以看到, 这个对象的ob_bytes直接指向内存, 而且这是一个可读的内存. 所以操作起来这个对象十分的方便

和上面劫持控制流的方法类似, 我们只需要用str伪造一个PyBytearrayObject, 然后写入字节码的办法来将这个Object合法化, 然后返回这个对象给我们正常使用, 那么就能够用来实现leak.

想要将object合法化, 我们需要有一个PyBytearrayObject的Type, 这个Type的地址可以使用Bytearray对象的__subclasshook__方法来获取. 类似于这样obj.__subclasshook__.__str__().split("at ")[1][:-1]

至于libc中地址的存储位置, 用的是id(sys.stdin)+0x20的位置, 这个位置有一个libc的地址, 那么我们将它leak出来就行

方法是将这个地址写入伪造的PyBytearrayObject的ob_bytes域, 然后我们就能通过 u64(str(fake_Bytearray_obj).ljust(8,'\x00'))[0]将libc成功leak出来

Getshell

前面已经提到过, 在劫持函数指针后进行函数调用的时候, 第一个参数是指向 fake_obj 开头的指针, 那么, 我们将伪造的fake_obj的前几个字节改为”/bin/sh\x00”即可getshell了
