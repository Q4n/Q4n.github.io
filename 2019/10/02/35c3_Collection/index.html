题目还给了test.py来帮助我们理解如何使用这个Collection库

server.py 中给出了远程服务器运行的代码, 是py2写的, 可以看出主要逻辑是加了一个沙箱

可以看到,删除了os模块, 只给我们留下了id hex print 和 range .

库文件分析

逆向技巧

了解C写的Python库的特点–>易于找到入口点

所以在这道题中入口是PyInit_Collection

还有就是, 在这个函数中用到了例如PyType_Ready之类的Python函数, 在Python源码或者文档中我们能够搜到签名int PyType_Ready (PyTypeObject *type), 传入的参数是个PyTypeObject, 我们一般需要定义出这个结构体才能更好的逆向, 因为可能需要看其中的一些参数, 一些导出的接口. 在linux驱动逆向中也是可能出现类似的问题.

解决思路是自己编译一个源码, 将带有debug信息的ELF用IDA打开, 利用ida的导出类型到c header的方法可以将类型直接从Python中提取出来.

然后用ida打开，选择file -> produce file -> create C header就可以导出到header，再在Collection的so库的这边的structure窗口insert -> add standard structure --> 选择导入的结构体, 比如说PyTypeObject, 就可以导入具体的类型信息了。然后在某个已知的函数参数, 修改类型, 就可以很方便的帮助我们逆向(因为在面向对象中, 很多都有继承关系, 比如修改了Type之后, 我们就能由PyTypeObject中的一些成员推测出这个类型是干什么的)

之后的基本方法就是看到python的函数，去查找签名，把类型改对。

so分析

主要逻辑: 这个类实现了一个handlers来存放每个Object的handler, 在新建一个Object的时候进行遍历, 假如handler相同, 则取出句柄, 否则就新建

漏洞点在getTypeHandler进入到listIsEquivalent函数中, 在判断handler的时候, 他先对Object中的元素进行了排序, 才进行每个元素是否相等的判断, 那么就会出现{"a":[1] , "b": 2}=={"b": 2,"a":[1]}的情况, 造成类型混淆. 之后通过 obj.get(“a”)[0]=”aa”进行访问, 修改他的值.

注意这里Collection对象是不同的, 相同的是他们指向的dict

还有一个注意点, Collection这个object中的int在Collection的slot中是直接存储整数, 这个是由so文件定义的
